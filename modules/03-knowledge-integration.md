# 模块 03：知识库整理

## 目标

把深度精读稿 + 用户自己的知识点 + 指定主题已有知识，重组成可长期迭代的论文主笔记和少量高价值知识节点。

## 严格范围

- 只读取状态文件绑定的 Obsidian 研究主题目录。
- 不默认扫描整个 Vault。
- 不直接写入；先生成提案。

## 输入

- 主论文 PDF
- 深度精读 `.md`
- 当前论文状态文件
- 指定主题 Obsidian 文件夹
- 可选 Zotero 高亮/批注/待解决问题/灵感

## 流程

### A. 自动串联已有材料

先整理出“研究背景 → 核心问题 → 理论基础 → 假设/出发点 → 方法 → 实验证据 → 结论 → 局限 → 知识关联”的半成品。

### B. 识别用户理解缺口

凡 `【我的理解】` 需要用户真正思考、但当前资料没有答案的地方，不得代写。

每次只问少量真正关键的问题，并优先问能改变主笔记结构的问题。

### C. 节点识别

把候选分成：

- `已存在 → 建议链接/补充`
- `未存在但复用价值高 → 建议新建`
- `内容重复 → 建议合并`
- `仅本文细节 → 留在论文主笔记，不建节点`

节点创建原则：控制粒度，避免碎片化。

### D. YAML/Properties

在生成最终提案前：

1. 说明 Properties 用途（检索、Dataview、状态、主题、citekey 等）；
2. 询问用户是否启用；
3. 未确认时不自动添加 YAML。

### E. 提案

生成 `knowledge-update-proposal.md`，至少包含：

- 拟创建/更新的文件
- 每个文件的目的
- 拟新增的双向链接
- 拟更新 MOC 的内容
- 哪些内容来自作者、用户、AI
- 风险/待核验项
- 变更摘要

### F. 用户确认后写入

只有用户明确确认后才允许：

- 创建最终论文主笔记
- 新建/更新知识节点
- 更新主题 MOC

写入后保留更新历史，并建议执行 Git diff/commit。

## 最终主笔记视角

每个核心主题下并列：

- `【作者观点】`：原论文支持
- `【我的理解】`：只能来自用户
- `【AI 分析】`：AI 的判断，必须与作者观点分开

没有用户理解时：

`【我的理解】暂无 / 待补充`

并可附一个思考提示，但不得把 AI 答案塞进“我的理解”。
