# 模块 02：深度精读

## 目的

把“看过论文”变成“理解方法、能解释关键公式、能判断实验是否支撑结论、能形成科研问题意识”。

输出为工作区 Markdown 中间稿，不直接进入 Obsidian。

## 原则

- 前半段偏教学，后半段偏科研分析。
- 按复杂度自适应篇幅，不设硬性字数上限，但避免逐段复述。
- 对长论文采用分段分析：背景/相关工作 → 方法 → 理论与公式 → 实验 → 结论/局限 → 汇总。
- 深度精读阶段默认做 2–5 篇少量横向对比，所有外部来源必须可核验。

## 教学部分

### 1. 阅读前置知识

只补理解本文确实需要的基础。每项回答：

- 是什么？
- 为什么本文需要？
- 读到哪一节会用到？

### 2. 核心研究问题

区分：作者直接写出的研究问题 vs AI 根据全文整理出的实际问题。

### 3. 整体论证链

优先用 Mermaid 表达：

```mermaid
flowchart LR
A[研究问题] --> B[理论/假设]
B --> C[方法设计]
C --> D[实验验证]
D --> E[结论]
```

仅在有帮助时生成。

### 4. 方法拆解

说明输入、输出、关键步骤、每一步解决什么问题、为什么这么设计。

### 5. 关键理论与公式

每个真正关键公式都按：

1. 原论文公式编号与定位；
2. LaTeX 重写；
3. 每个变量含义；
4. 公式直觉；
5. 使用前提/假设；
6. 它在整体方法中的作用；
7. 必要时做基础推导。

默认解释深度以 B 为主；核心部分升级到 C（必要时从基础概念推导）。

### 6. 关键图、表、流程图

每个重点图表回答：

- 它想证明什么？
- 横纵轴/模块/变量是什么？
- 读图时最该看哪里？
- 它是否真的支持作者结论？
- 对未来实验/写作有什么可借鉴之处？

## 科研分析部分

### 7. 实验设计

根据论文类型重点分析：数据/样本、基线、控制变量、评价指标、消融、统计、重复实验、硬件条件、误差来源等。

### 8. 创新点拆解

必须区分：

- 作者声称的创新；
- 从全文能核验的创新；
- AI 对创新程度的判断。

### 9. 实验是否支撑核心主张

用“主张 → 证据 → 是否充分 → 缺口”方式分析。

### 10. 局限性

分为：

- 作者明确承认的局限；
- 根据原文可分析出的局限；
- 外部对比暴露出的局限。

### 11. 少量横向对比

默认 2–5 篇。优先：原始论文、正式期刊/会议页面、DOI、arXiv。聚合平台主要用于发现。

比较维度：问题、核心方法、实验条件、优势、局限、与本文差异。

### 12. 简要复现清单

控制篇幅，只列：

- 数据/设备
- 关键参数/超参数
- 软件/模型/算法依赖
- 作者公开代码或补充材料（仅提示，不擅自分析）
- 复现最可能缺失的信息
- 最值得自己动手实现的环节

### 13. 对选题的启发

只给“从本文能得到哪些研究思维启发”，不自动推荐下一篇论文。

### 14. 主动回忆与研究式问题

5–10 个高价值问题，优先围绕：

- 为什么这样设计？
- 哪个实验最能证明核心模块有效？
- 关键假设是什么？
- 如果换一个条件，方法会失效吗？
- 哪个局限可能发展成研究问题？
